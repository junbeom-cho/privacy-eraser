# ADR-005 : 하나라도 실패하면 전체를 실패로 본다

* 작성일자 : 2026-08-10
* 작성자 : 조준범

## 1. 배경

이관은 여러 단계로 이루어집니다. 테이블 적재가 끝난 뒤 인덱스, 제약조건, 코멘트, 시퀀스를 만듭니다.
인덱스 하나가 실패해도 데이터는 이미 다 옮겨진 상태라, 부분 성공으로 처리할 수 있습니다.

하지만 **일부만 제약조건이 걸린 스키마는 완전한 줄 알고 쓰이면 더 위험합니다.**
그 위에서 개발하는 사람은 없는 제약조건을 있다고 믿게 됩니다.

## 2. 결정

하나라도 실패하면 실행 전체를 `FAILED` 로 기록합니다. 재이관은 처음부터 다시 합니다.

이 결정 때문에 **사전 검사**가 필요해졌습니다. 마스킹된 컬럼에 PK·UNIQUE 가 걸려 있으면 값이 겹쳐
반드시 실패하므로, 데이터를 옮기기 전에 막습니다.

## 3. 결과

- 실제로 `EMPLOYEES.EMAIL` 이 `EMP_EMAIL_UK` 에 걸려 시작 단계에서 차단됐습니다.
  아무것도 옮기지 않은 상태로 사유를 알려줍니다.
- 검수 화면에도 `PK` · `UQ` 배지를 표시해, 이관을 시작하기 전에 알 수 있게 했습니다.
- 실패한 실행이 남긴 테이블은 지우지 않습니다. 재이관이 어차피 덮어쓰고,
  삭제 루프를 오류 처리기 안에 두는 것이 더 위험하다고 판단했습니다.
