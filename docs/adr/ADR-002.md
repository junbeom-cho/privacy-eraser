# ADR-002 : 데이터를 앱으로 꺼내지 않는다

* 작성일자 : 2026-08-10
* 작성자 : 조준범

## 1. 배경

수백만 행을 마스킹해 옮겨야 합니다. 애플리케이션이 JDBC 로 읽어 가공하고 다시 넣는 방식이
가장 먼저 떠오르는 방법입니다.

그 방식은 네트워크를 두 번 타고, **개인정보 원문이 애플리케이션 메모리에 올라갑니다.**
힙 관리와 배치 크기 조정도 따라옵니다. 개인정보를 다루는 도구가 그 데이터를 자기 메모리에
올리는 것부터 줄일 이유가 충분했습니다.

## 2. 결정

원본과 이관 대상이 **같은 Oracle 인스턴스**라는 전제를 두고, 마스킹을 SQL 식으로 표현해
`CREATE TABLE ... AS SELECT` 한 문장으로 구조와 데이터를 함께 만듭니다.

```sql
CREATE TABLE "EDIT"."EMPLOYEES" AS
SELECT CASE WHEN PHONE IS NULL THEN NULL
            WHEN LENGTH(TO_CHAR(PHONE)) <= 4 THEN '****'
            ELSE SUBSTR(...) || '****' END AS "PHONE"
  FROM "HR"."EMPLOYEES"
```

## 3. 결과

- 134개 테이블 · **489만 행 · 1.1GB 가 41초**에 끝납니다.
- 데이터가 DB 밖으로 나오지 않습니다.
- 같은 인스턴스가 아니면 쓸 수 없다는 제약이 생겼습니다. 받은 DB 를 자기 서버에 복원해 쓰는
  실제 사용 상황에서는 문제가 되지 않았습니다.
- 마스킹된 컬럼은 `VARCHAR2` 가 됩니다. `*` 는 숫자·날짜 타입으로 돌아갈 수 없습니다.
