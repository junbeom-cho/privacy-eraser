# ADR-012 : 키워드는 토큰과 컬럼명 전체에 맞고, 부분 일치는 하지 않는다

* 작성일자 : 2026-08-11
* 작성자 : 조준범

## 1. 배경

키워드 판정은 컬럼명을 `_` 로 쪼갠 토큰과만 대조했습니다. `OWNR_BMNO` 는 `ownr`, `bmno` 가 됩니다.

그래서 **컬럼명을 통째로 키워드에 넣으면 아무것도 걸리지 않았습니다.** 오타도 아니고 에러도 아닌데
조용히 0개가 나옵니다. 넣은 사람은 왜 안 되는지 알 방법이 없습니다.

실제 컬럼명이 `OWNR_BMNO`, `NEW_BMNO`, `USGSRHLD_BMNO` 처럼 생긴 스키마에서는
`bmno` 하나로 41개가 걸립니다. 그중 하나만 지정하려면 컬럼명 전체를 쓸 수 있어야 합니다.

## 2. 결정

토큰 하나와 맞거나, **컬럼명 전체**와 맞으면 걸리는 것으로 바꿉니다.

```java
tokens.contains(keyword.getWord()) || fullName.equals(keyword.getWord())
```

**부분 일치는 하지 않습니다.** `ownr_bm` 이 `OWNR_BMNO` 에 걸리면 토큰 경계가 무너져
의도치 않은 컬럼이 딸려옵니다. 키워드를 쓰는 이유가 사라집니다.

우선순위 규칙은 그대로 둡니다. 기존 "더 긴 키워드가 이긴다" 로 컬럼명 전체가 토큰보다
자연히 앞섭니다. 새 규칙을 넣지 않았습니다.

## 3. 결과

- 실제 스키마에서 `UNITY_TWVH_APLY_RCPT_NO` 를 키워드로 넣으니 33개 테이블의 그 컬럼만
  걸렸습니다. 토큰만 겹치는 컬럼은 하나도 딸려오지 않았습니다.
- 엑셀 정의서와 쓰임이 갈립니다. 정의서는 `테이블 + 컬럼` 하나를 짚고,
  컬럼명 전체 키워드는 **모든 테이블의 같은 이름**을 한꺼번에 잡습니다.
- 키워드 입력칸 안내를 고쳤습니다. 되는 줄 모르면 없는 기능과 같습니다.
