# ADR-011 : 컬럼 정의서는 키워드가 아니라 사용자 지정으로 반영한다

* 작성일자 : 2026-08-11
* 작성자 : 조준범

## 1. 배경

비식별화할 컬럼을 이미 정해둔 **컬럼 정의서**(엑셀)가 있는 현장이 많습니다. 그 목록을 도구에
넣을 방법이 필요했습니다.

처음 떠오른 것은 키워드였습니다. 이미 키워드 입력 화면이 있으니 거기에 일괄 입력이나 엑셀 업로드를
붙이면 된다고 봤습니다.

그런데 성격이 다릅니다. **키워드는 이름 규칙이라 의도한 것보다 항상 더 많이 걸립니다.**
실제 데이터에서 `bmno` 는 41개 컬럼에, `nm` 은 38개 컬럼에 걸립니다. 정의서에 적힌 것이
`T_BMRG_TWVH_M.OWNR_BMNO` 하나라면, 키워드로는 그 하나만 가리킬 방법이 없습니다.

## 2. 결정

정의서를 **사용자 지정**(`column_override`)으로 반영합니다. 키워드 쪽은 손대지 않습니다.

검수 화면의 "직접 지정"이 이미 `테이블 + 컬럼 + 마스킹 여부 + 정책` 을 건별로 저장하고 있고,
판정 우선순위에서 키워드를 이깁니다. 정의서가 정확히 그 형태라 새 개념을 만들 이유가 없었습니다.

```
사용자 지정(= 정의서) > Undo 키워드 > Do 키워드 > 미매칭
```

양식은 **머리글만 있는 빈 파일**로 줍니다. 현재 판정을 채워 내려주면 통째로 다시 올릴 때
모든 컬럼이 사용자 지정이 되어 키워드가 죽습니다. 옮겨 적을 목록이 이미 따로 있는 것이 전제이기도 합니다.

## 3. 결과

- **적은 줄만 바뀝니다.** 3,207개 컬럼짜리 스키마에서 두 줄만 적어 올리면 두 개만 지정되고
  나머지 3,205개는 그대로였습니다.
- 판정 규칙을 건드리지 않아 키워드가 그대로 살아 있습니다.
- 원본에 없는 테이블·컬럼은 반영하지 않고 몇 행이 왜 안 됐는지 돌려줍니다.
  이름을 옮겨 적다 틀리면 조용히 빠지는 대신 드러납니다.
- xlsx 를 읽어야 해서 `poi-ooxml` 의존성이 늘었습니다. CSV 면 의존성이 없지만, 윈도우 엑셀이
  CSV 를 CP949 로 저장해 한글이 깨지고 저장할 때마다 경고가 뜹니다. 매번 겪을 마찰이라 xlsx 를 택했습니다.
