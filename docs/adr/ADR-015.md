# ADR-015 : 형식이 섞인 컬럼은 고정값으로 바꾼다

* 작성일자 : 2026-08-14
* 작성자 : 조준범

## 1. 배경

부분 마스킹은 **위치**로 동작합니다. 앞에서 N자, 뒤에서 N자입니다. 그런데 같은 컬럼 안에
형식이 섞여 있으면 같은 위치가 서로 다른 의미가 됩니다.

```
010-1234-5678   가운데 4자리 = 6~9번째
01012345678     가운데 4자리 = 4~7번째
```

실제 데이터에서 확인했습니다. `T_BMCM_TWVH_BTCB_H.TELNO` 는 하이픈이 있는 값 500건과
숫자만 있는 값 15건이 한 컬럼에 섞여 있었습니다.

그 15건을 열어보니 더 나빴습니다. `0`, `2830451` 처럼 **전화번호도 아닌 값**이었습니다.
부분 마스킹은 이런 값을 `*` 로 바꿀 뿐, 유효한 모양으로 만들어주지 못합니다.

형식을 정규식으로 판별해 형식마다 다른 자리를 가리는 방법을 먼저 검토했습니다.
동작은 하지만 **형식 목록이 끝없이 늘어납니다.** 전화번호만 해도 내선, 해외번호, `+82` 접두가
있고 이름은 2~4자에 외국인명까지 섞입니다. 관리 비용이 얻는 것보다 큽니다.

## 2. 결정

**고정값 치환**을 세 번째 방식으로 넣습니다. 컬럼의 모든 값을 지정한 값 하나로 바꿉니다.

```
010-1234-5678  →  01011111111
01012345678    →  01011111111
0              →  01011111111
```

무엇이 들어오든 결과가 같아 **형식을 판별할 필요가 없습니다.** SQL 은 리터럴 하나라
`CASE` 도 정규식도 없습니다.

값은 컬럼마다 지정합니다. 키워드에 걸어두면 그 이름이 걸리는 컬럼 전부에 적용됩니다.

**NULL 은 NULL 로 둡니다.** 원래 비어 있던 값을 채우면 없던 데이터가 생깁니다.

이로써 비식별화 방식이 셋이 됩니다.

| 방식 | 남는 정보 | 값의 분포 | 형식·타입 | PK·UK |
|---|---|---|---|---|
| 부분 마스킹 | 일부 | 유지 | 유지 | ✕ |
| 해시 | 없음 | 유지 (고유) | 파괴 | ○ |
| **고정값** | 없음 | **파괴** | **유지** | ✕ |

해시와 고정값은 정반대입니다. 해시는 값이 전부 달라야 할 때, 고정값은 같아도 될 때 씁니다.
겹치는 용도가 없어 둘 다 둡니다.

## 3. 결과

- 형식이 섞인 컬럼을 규칙 하나로 처리합니다. 형식 목록을 유지할 필요가 없습니다.
- 쓰레기 값도 **유효한 모양**이 됩니다. 그 위에서 개발하는 쪽에는 이쪽이 낫습니다.
- **모든 행이 같은 값이 됩니다.** 그 컬럼으로 구분·그룹핑하는 기능을 개발한다면 쓸 수 없습니다.
  그럴 때는 해시를 씁니다.
- 타입을 지킬 수 있습니다. 지금 마스킹된 컬럼은 `*` 가 섞여 전부 `VARCHAR2` 가 되는데,
  고정값은 숫자 컬럼에 숫자를 넣을 수 있습니다.
- **PK·UNIQUE 에는 쓸 수 없습니다.** 전부 같은 값이라 부분 마스킹과 똑같이 겹칩니다.
  [ADR-005](ADR-005.md) 의 사전 검사가 그대로 잡아내므로 새 규칙이 필요 없습니다.
- 고정값이 컬럼 길이보다 길면 적재 중 `ORA-12899` 로 실패합니다. 검수 화면의
  `정책이 컬럼 길이보다 김` 경고에 얹고, 이관 시작 전 사전 검사에도 넣습니다.
  엑셀로 올린 값까지 걸러야 하기 때문입니다.
