# ADR-009 : 휴지통(BIN$) 객체를 메타데이터에서 제외한다

* 작성일자 : 2026-08-10
* 작성자 : 조준범

## 1. 배경

Windows 환경에서만 이관이 실패했습니다. Mac 에서는 같은 코드가 정상 동작했습니다.

```
ORA-00942: table or view "TEST_USER"."BIN$WF2nbc0HWAHgYwIAHKwRZQ==$0" does not exist
```

DataGrip 으로 확인하면 테이블이 분명히 존재하는데 없다고 나오는 점이 이상했습니다.
추측을 확정으로 바꾸기 위해 **재현**했습니다. 원본/이관 대상 역할 스키마를 만들고, 코멘트가 달린
테이블을 `PURGE` 없이 지운 뒤 같은 동작을 실행하자 동일한 에러가 났습니다.

원인은 `PURGE` 없이 `DROP TABLE` 하면 테이블이 휴지통에 `BIN$...` 이름으로 남고
**코멘트도 딸려 남는다**는 점, 그리고 뷰마다 이것을 걸러주는 정도가 다르다는 점이었습니다.

| 조회 뷰 | 휴지통 객체 |
|---|---|
| `ALL_TABLES` · `ALL_INDEXES` · `ALL_CONSTRAINTS` | 안 보임 |
| **`ALL_TAB_COMMENTS` · `ALL_COL_COMMENTS`** | **보임** |

Mac 에서 재현되지 않은 이유는 Oracle 버전 차이가 아니라 **데이터 차이**였습니다.
이쪽 스키마는 모든 DROP 에 `PURGE` 를 붙인 스크립트로 만들어져 휴지통이 비어 있었습니다.

## 2. 결정

메타데이터 조회에 `table_name NOT LIKE 'BIN$%'` 조건을 겁니다.

코멘트 조회가 실제 원인이지만, Oracle 버전에 따라 다른 뷰도 노출할 수 있어
테이블·인덱스·제약조건 조회에도 같은 조건을 걸었습니다.

## 3. 결과

- 사용자가 `PURGE` 없이 테이블을 지워도 이관이 깨지지 않습니다.
  DataGrip 의 Drop 은 기본적으로 `PURGE` 를 붙이지 않아 흔히 생길 수 있는 상황입니다.
- **화면에 보이는 것과 코드가 보는 것이 다를 수 있다**는 사례로 남았습니다.
- 환경이 달라야만 드러나는 결함이 있다는 것을 확인했습니다.
  같은 코드가 한쪽에서만 실패할 때는 코드가 아니라 데이터를 먼저 의심해야 합니다.
